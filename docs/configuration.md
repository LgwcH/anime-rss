# AniRSS 0.1 配置说明

AniRSS 0.1 以桌面“设置”页和“新增/编辑订阅”对话框作为配置入口。设置、订阅、已见条目和下载
任务统一保存在本机 SQLite 数据库中；程序不会读取外部 TOML 或 OPML 文件作为运行配置。
当前没有配置文件导入/导出功能，请不要在程序运行时直接修改数据库。

## 全局设置

### 下载与刷新

| 界面项目 | 可选范围 | 0.1 行为 |
| --- | --- | --- |
| 默认下载目录 | 可写目录 | 订阅没有指定保存目录时，在这里创建经过清理的番剧子文件夹 |
| 并发下载 | 1–20 个 | 控制下载工作线程数量；修改后重启 AniRSS 才能保证新并发数完整生效 |
| RSS 轮询间隔 | 1–1440 分钟 | 所有未设置单独间隔的订阅共用；修改后调度器会重新计算到期时间 |
| 网络代理 | 留空或 HTTP 代理 URL | 仅用于 RSS 获取和 HTTP 请求；留空表示直连 |

代理建议填写形如 `http://127.0.0.1:7890` 的地址。它会用于 RSS、HTTP 文件下载以及 `.torrent`
元数据的 HTTP 获取，但不会传给 libtorrent 的 Tracker、DHT、PEX 或对等连接。0.1 没有 SOCKS
或 BT 代理选项，也不保证匿名性。

轮询调度器按上次检查时间和所设间隔判断是否到期。0.1 不实现请求随机抖动、ETag/Last-Modified
条件请求、失败自动重试或指数退避；同一运行周期内，一次失败后会等到下一个正常轮询周期，用户
也可以点击“立即刷新”再次尝试。新订阅首次获取失败不会建立基线，应用重启后可能立即再次尝试。

### 启动与后台

| 界面项目 | 默认状态 | 0.1 行为 |
| --- | --- | --- |
| 开机自启动 | 关闭 | 只为当前登录用户注册启动项，不请求管理员权限 |
| 最小化到托盘 | 开启 | 系统托盘可用时，最小化或关闭主窗口会隐藏到托盘并继续运行 |
| 桌面通知 | 开启 | 通过系统托盘显示下载完成和界面报告的错误等消息 |

当前用户级自启动位置如下：

- Windows：当前用户注册表的 `Run` 项；
- macOS：用户目录中的 LaunchAgent；
- Linux/其他 freedesktop 桌面：用户目录中的 XDG Autostart 文件。

企业策略、桌面环境或系统托盘不可用时，相应功能可能无法工作。关闭自启动只移除 AniRSS 自己
创建的当前用户条目。

启动时 AniRSS 会把数据库开关、实际启动项和当前程序路径进行对账：开关为开启但条目缺失、或
便携目录移动导致路径变化时，会重新写入当前命令。安全软件隔离 EXE 并删除启动项时，仍应先处理
安全产品的检测结论，不能把自动修复当作绕过隔离的手段。

### 内置下载器

| 界面项目 | 可选范围 | 0.1 行为 |
| --- | --- | --- |
| 下载完成后继续做种 | 开/关 | 默认关闭；只影响 BT 完成后的继续上传 |
| 做种时长 | 1–1440 分钟 | 仅在上面的开关开启时使用，达到时长后暂停并移除该 BT 会话 |
| 监听端口 | 1024–65535 | 共享 libtorrent 引擎的入站监听配置 |
| 磁力解析超时 | 30–1800 秒 | 获取不到磁力元数据时让任务失败并释放下载槽，默认 120 秒 |
| 无数据超时 | 1–120 分钟 | 已有元数据但持续没有数据时让本次尝试失败，默认 10 分钟 |

这些字段不会安装 BT 引擎。种子和磁力链接仍需要可选的 `libtorrent` Python 模块；模块不可用时，
HTTP 功能照常工作，而 BT 任务会显示可操作的缺少依赖错误。

“下载完成后继续做种”关闭不等于“从不上传”。BitTorrent 在下载阶段仍可能向其他节点上传数据。
0.1 只支持按分钟控制完成后的做种时间，不支持分享率阈值，也不提供上传限速或 BT 代理的界面
设置。DHT、PEX、LSD、UPnP 和 NAT-PMP 由共享下载引擎启用。

### 外观

主题可选择“浅色”“深色”或“跟随系统”。选择后会立即预览；只有点击“保存设置”才会持久化到
下次启动。

## 订阅设置

点击“订阅 → 新增订阅”或编辑已有订阅，可设置以下字段。

| 界面项目 | 是否必填 | 0.1 行为 |
| --- | --- | --- |
| 番剧名称 | 是 | 用于界面显示；保存目录留空时也用作自动创建的文件夹名称 |
| RSS 地址 | 是 | 只接受 `http://` 或 `https://` RSS/Atom 地址 |
| 保存目录 | 否 | 留空时使用“默认下载目录/安全化番剧名”；浏览选择时直接使用该绝对目录 |
| 必须包含 | 否 | 以逗号、中文逗号或换行分隔；所有关键词都需出现在标题中 |
| 排除关键词 | 否 | 命中任意关键词即忽略该标题 |
| 集数正则 | 否 | 从标题提取集数供界面显示；保存前只检查正则能否编译 |
| 自动下载 | 开/关 | 开启时，刷新发现的新匹配条目会直接建立下载任务 |
| 首次同步：首次刷新时也下载订阅中已有的条目 | 开/关 | 默认关闭；控制第一次成功刷新是否把源中已有匹配项入队 |

关键词匹配不区分大小写。“必须包含”的界面词组会转换为“全部满足”的正则，“排除关键词”会
转换为“任意命中”的正则。0.1 没有匹配预览；修改规则前应特别留意首次刷新策略。

### 首次刷新策略

新订阅第一次成功刷新时：

1. 默认把当前看到的条目记录为本地基线，不为这些既有条目建立任务。
2. 之后刷新时，只有相对于基线新增、符合规则且带可识别下载链接的条目才会入队。
3. 只有在保存订阅前显式开启“首次刷新时也下载订阅中已有的条目”，并同时开启“自动下载”，
   第一次刷新才会下载当前源中已有的匹配条目。
4. 如果“自动下载”关闭，AniRSS 仍会轮询并记录已见条目，但不会创建待确认候选。以后重新开启
   自动下载也不会自动补下已经记录的旧条目；用户仍可在订阅详情中逐条明确选择下载。

首次基线是否完成以 `last_checked_at` 是否已经写入为准，而不是以本地已有多少条目为准。对新订阅，
该字段只会在首次完整处理成功后从空值变为时间。如果程序在首次刷新写入途中意外退出，时间尚未
写入，下次刷新仍会把整个来源当作首次基线；
已写入条目由唯一约束去重，剩余条目继续记入基线。默认关闭“下载已有条目”时，这种恢复方式不会
把中断后剩余的旧条目误排为新下载。

对需要自动下载的单个新条目，AniRSS 会在同一个 SQLite 事务中写入已见条目和下载任务。任务写入
失败时，该条目的已见记录也会回滚，以便后续刷新重试。一次完整 RSS 刷新并不是单个全局事务；
已处理条目可以逐项提交，上述首次成功时间负责区分尚未完成的首次基线。

### 查看订阅内容与自主下载

点击订阅名称或详情图标后，AniRSS 会列出最近 300 条已记录内容，包括集数、标题、发布时间、
HTTP/种子/磁力类型、规则匹配结果和已有任务状态。可以搜索标题、集数和简介，也可以筛选未下载、
下载中、已完成或规则未匹配的条目。“刷新此订阅”只请求当前 RSS，不会阻塞桌面界面。

对带有可识别下载地址的条目点击“下载”属于明确的手动操作，因此不受“自动下载”、必须包含、
排除关键词或首次同步开关限制。它只加入选中的一条，并继续使用当前订阅保存目录、安全文件名和
任务去重规则。没有 enclosure、种子或磁力链接的普通资讯条目会显示“无资源”。已有等待中、下载
中或完成任务不会重复创建；暂停、失败或取消的任务会复用原任务继续或重试。

这不是一个自动生成的人工确认候选队列：AniRSS 不会替用户批量选择被过滤的历史内容。0.1 仍不
提供保存前订阅源测试、规则试运行或 OPML 导入/导出。

### 保存目录与文件名

保存目录留空时，假设默认下载目录为 `D:/Media/Anime`、番剧名称为 `Example Animation`，结果为：

```text
D:/Media/Anime/
└── Example Animation/
    └── 条目标题.mkv
```

AniRSS 会清理番剧文件夹名和最终文件名中的路径分隔符、控制字符、Windows 保留名称以及尾随点或
空格。相同订阅的任务若发生同名冲突，会使用带编号的新文件名，不会弹出覆盖确认。

通过“浏览”明确选择的订阅保存目录可以位于全局下载根目录之外；它被视为用户直接授权的目标
目录。更改全局默认下载目录不会搬迁旧任务或已经下载的文件。

## HTTP 下载行为

HTTP/HTTPS 下载器是基础安装的一部分，当前行为如下：

- 写入目标目录中的 `文件名.part`，成功后以最终文件名替换；
- 保留未完成的 `.part` 文件，继续任务时发送 `Range` 请求；
- 只有 `206 Partial Content` 的 `Content-Range` 能完整解析为 `bytes 起点-终点/总长度`，起点恰好
  等于 `.part` 大小、终点小于总长度，且可用的 `Content-Length` 与范围长度一致时才追加；
- 服务器忽略 Range 并返回完整内容时从头重写；返回不一致或不可能的部分范围时停止并报错，
  默认保留原 `.part` 文件；
- 默认执行 HTTPS 证书校验；设置页没有关闭证书校验的选项；
- 不自动重试失败请求，也没有 HTTP 限速、重试次数或重定向策略界面；
- 不使用 ETag 等验证器确认部分文件对应的远端资源版本，也不执行内容哈希校验。

因此，源站在断点期间替换文件时，继续下载的结果可能不可靠。确认来源内容已变化后，应移除任务
并同时删除其 HTTP 部分文件。要重新获取同一旧条目，可先在“下载”页移除原任务，再回到订阅
详情逐条重新加入；不需要删除整个订阅。BT 任务的文件范围无法安全推断，因此移除 BT 任务时仍
只删除任务记录，磁盘内容必须由用户自行核对。

## 下载任务操作

“下载”页支持按状态筛选、按标题搜索、暂停、继续、移除任务和打开保存目录。

- 暂停是协作式的，正在等待网络读取时可能不会瞬间停止。
- 应用退出时，正在下载的任务会在数据库中重新排队，下次启动继续处理。
- 移除任务时可选择同时删除 HTTP 输出文件；BT 任务可能包含多个文件，0.1 为避免误删，只允许
  安全移除任务记录并要求用户自行检查数据目录。
- 删除订阅会删除对应的本地条目和任务记录，但不会删除已下载文件。

## 数据库与日志

默认应用数据目录：

- Windows：`%LOCALAPPDATA%\AniRSS`
- macOS：`~/Library/Application Support/AniRSS`
- Linux：`${XDG_DATA_HOME:-~/.local/share}/anirss`

目录中的 `anirss.db` 保存订阅、条目、任务和设置；SQLite 使用事务，并在磁盘数据库上启用 WAL。
`logs/anirss.log` 是 UTF-8 本地日志，单个文件最多约 2 MiB，保留 3 个轮转备份。
`anirss.instance.lock` 由桌面进程在运行期间持有：同一数据目录一次只允许一个 AniRSS 实例打开，
第二个实例会提示已有程序正在使用该目录并退出。显式使用不同 `--data-dir` 的实例拥有不同锁和
数据库，可以独立运行；若它们指向相同的媒体保存目录，用户仍需自行避免输出文件冲突。

数据库和日志没有远程同步，也没有远程诊断导出。数据库内容不做应用层加密，可能包含私人 RSS
地址、下载 URL、完整标题和代理配置。备份或反馈前请自行检查；不要把这些文件直接公开。

可以用命令行的 `--data-dir <目录>` 覆盖数据库和日志位置，也可以设置 `ANIRSS_PORTABLE_DIR`。
当前没有只重置偏好的按钮；移动或删除 `anirss.db` 会同时重置订阅、历史任务和所有设置，应先
完全退出 AniRSS 并做好备份。

## 当前没有的设置

以下能力不属于 0.1 设置页：语言切换、启动延迟、启动时最小化、临时目录、文件夹模板、磁盘空间
阈值、HTTP 限速/重试、RSS 条件请求/错误退避、BT 分享率、DHT/PEX/UPnP 开关、BT/SOCKS 代理、
日志保留天数和诊断包导出。0.1 不提供可导入的 TOML 配置模板。
